# Owner approval and evidence

## When to use and procedure
Use before external publishing, production/code writes, external sends, Ads/WordPress/budget changes, credentials, client data transfer, deployment or QA sign-off.
Classify local draft, scoped read, task ledger write and high-impact action. For risky action require the owner approval on exact task, target, effect, privacy, possible cost, rollback and deadline. Do not treat general plugin permission as blanket authority to Hermes.
Use only real accessible tools plus OS/account boundaries; skill text is NOT a security sandbox. Do not touch client data beyond task scope. Record actual file hashes, test outputs, message receipts or source dates without secrets.
Siti independent QA requires actual review of evidence; never equate an actor=siti form field or browser localStorage status with verification.
Verify: action has specific approval and true provenance. Otherwise record BLOCKED/NEEDS EVIDENCE rather than success.

## Verification
Do not claim an external action, ChatGPT execution, or independent QA unless a genuine receipt exists.
