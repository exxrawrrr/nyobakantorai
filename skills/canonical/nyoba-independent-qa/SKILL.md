# Siti independent QA

## When to use and procedure
Use for claims of completed engineering, data, creative, provider or external work. Set exact acceptance criteria and version before reviewing the original source/artifact. Inspect actual tool receipts, code/test output, source dates, negative tests, user approval and privacy scope. Distinguish built, tested on local, deployed and truly live; if tools or evidence are unavailable say NOT TESTED. Give PASS/FAIL/NEEDS EVIDENCE with actionably reproducible fixes and residual risk. A local browser actor=siti or an author-written PASS cannot create independent QA evidence. the owner still owns production approval.

## Verification
Report actual evidence, scope and unverified limitations. A skill is instructions, not a new executable tool or permission.
