# v0.4 Release Decision

Date: 2026-09-29  
Candidate branch: `v0.4/modular-workforce`  
PR: #11 -> `prd/next-modular-workforce`

## Decision

**HOLD stable promotion.**

The v0.4 candidate is structurally healthy enough to continue review, but it is **not yet eligible to be called a stable v0.4 release** and must not be tagged or promoted to `main` as if all evidence gates were complete.

PR #11 remains a draft staging PR. A merge into `prd/next-modular-workforce` would still be staging, not a public v0.4 shipment.

## Why promotion is held

The following evidence-dependent items are deliberately deferred and remain truthfully open:

1. **Cross-harness behavioral parity** — static exports and the self-service parity runner exist for Hermes/Codex/Gemini/Copilot, but reviewed live multi-harness behavioral parity remains `UNPROVEN`.
2. **Cognee canonical live memory-provider evaluation** — the self-service HTTP adapter + isolated eight-case runner is implemented and deterministically verified, but no reviewed user/provider live result has been committed to the canonical memory benchmark. Canonical Cognee status therefore remains `NOT_RUN / UNPROVEN`.
3. **Browser Use canonical live evaluation** — the self-service Browser Use adapter + isolated six-case runner is implemented and deterministically verified, but no reviewed user/provider live result has been committed to the canonical provider benchmark. Playwright MCP remains the only `EVALUATED_CANDIDATE`; Browser Use canonical status remains `NOT_RUN / UNPROVEN`, so no head-to-head winner is claimed.
4. **Real-task baseline evidence** — collection has started at **1/20** eligible direct owner tasks. The first eligible case ended `NEEDS_EVIDENCE`; the publication gate remains closed.
5. **Broader real-workflow coverage** — the temporary plan's goal of at least one evidence-backed real workflow per major department has not been demonstrated.
6. **Fresh-install release matrix** — deterministic installer/pack tests exist, but a final release decision still needs explicit clean-machine one-worker/subset/full/upgrade/uninstall coverage across the intended release platforms.
7. **Existing non-v0.4 product gaps** — live ads provider adapters, original art for the ten newer workers, and complete office/UI storage migration remain open in `ROADMAP.md`.

These are not converted into success claims merely because scaffolding, contracts, or deterministic tests exist.

## Evidence already strong enough to retain

The candidate does have material verified progress:

- signed Ed25519 execution receipts with replay/freshness/binding/runtime-trust adversarial coverage;
- deterministic memory isolation and M3 reviewer provenance enforcement;
- deterministic personality-governance invariance across all 16 baseline employees;
- controlled live-model Fikri evaluation: 5/5 downstream pass, zero critical losses, 41.10% average estimated context reduction, and 100% protected/source fidelity on the recorded synthetic regression set;
- Playwright MCP controlled live evaluation: 6/6 contract cases, zero false-successes, no mutation POST, no auth-cookie leakage, and truthful timeout/partial recovery;
- Browser Use self-service adapter/runner with pinned CLI contract, disposable loopback target, temporary isolated browser profile, server-side mutation/auth evidence, and no automatic installation/login;
- Cognee self-service HTTP adapter/runner with pinned integration contract, run-owned datasets, profile isolation/negative contamination, provenance/export/delete verification, secret pre-write rejection, explicit shared promotion, and verified cleanup;
- cross-harness self-service parity runner for Hermes/Codex/Gemini/Copilot with pinned runtime sources, disposable skill activation, exact protected atoms, temporary workspaces, and bounded evidence;
- real-task baseline collection tooling with recorder-snapshot audit, fail-closed merge, duplicate direct-source rejection, exact remaining-count reporting, READY_FOR_REPORT preparation, and no automatic canonical overwrite/publication;
- real-task anti-theater gate that rejects sandbox/fictional/generated derivatives and currently preserves one real owner case as a failure/NEEDS_EVIDENCE result rather than greenwashing it;
- Linux, Windows, and minimum-version verification gates on the candidate branch.

## Claim limits that remain mandatory

Use these boundaries in README, release notes, and reviews:

```text
cataloged != installed != connected != authorized != executed != succeeded != verified
valid signed receipt != external action correctness != independent verification
static packaging compatibility != behavioral parity
controlled synthetic live-model evaluation != general real-world reliability
application-level permission policy != OS/container/process isolation
```

## Promotion path

Stable v0.4 promotion is allowed only after an explicit future decision:

1. resolve or explicitly re-approve the remaining deferred evidence items for the intended release scope;
2. update the real-task/provider records without inflating claims;
3. make PR #11 or a successor candidate reviewable against the final permanent docs;
4. promote through an explicit PR/merge path to `main`;
5. rerun the full verification and release gate from the **final promoted main commit**;
6. only then create a v0.4 tag/release.

The current candidate branch must not be tagged as stable.
