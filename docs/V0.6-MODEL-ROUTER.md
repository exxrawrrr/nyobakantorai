# v0.6 Model Router — CHAT 05

Status: **IMPLEMENTED FOR ROUTE-DECISION LAYER**  
Date: 2026-10-01  
Baseline: `main@634bdcd76d538d92d80ac31c4454ce469652cae6`

CHAT 05 adds a deterministic provider-neutral Model Router.

It selects among supplied model/runtime candidates using explicit requirements and policy facts. It does **not** execute inference or call provider APIs.

## 2. Task classes

v1 supports:

- `FAST`
- `REASONING`
- `VISION`
- `CODING`
- `LOCAL_SENSITIVE`

The class is a requirement category, not a provider name.

## 3. Inputs

Routing considers:

- task class;
- modality;
- reasoning depth;
- minimum context window;
- optional latency target;
- estimated input/output tokens;
- optional hard USD budget;
- privacy/locality;
- fallback permission;
- provider allow/deny policy;
- cloud permission;
- provider health.

Provider health states:

- `HEALTHY`
- `DEGRADED`
- `DOWN`
- `UNKNOWN`

`DOWN` and `UNKNOWN` are ineligible.

## 4. Candidate facts

Each candidate describes:

- model ID;
- provider ID;
- runtime ID;
- supported classes/modalities;
- max reasoning depth;
- LOCAL/CLOUD locality;
- context window;
- p95 latency;
- nullable input/output pricing per million tokens;
- enabled flag.

A candidate record does not prove the provider is connected, authorized, or healthy. Health is supplied separately in the request snapshot.

## 5. Hard filters

A candidate is rejected when any required constraint fails.

Reason codes include:

- `CANDIDATE_DISABLED`
- `TASK_CLASS_UNSUPPORTED`
- `MODALITY_UNSUPPORTED`
- `REASONING_INSUFFICIENT`
- `CONTEXT_TOO_SMALL`
- `PROVIDER_NOT_ALLOWED`
- `PROVIDER_DENIED`
- `LOCALITY_REQUIRED`
- `CLOUD_FORBIDDEN`
- `PROVIDER_DOWN`
- `PROVIDER_HEALTH_UNKNOWN`
- `LATENCY_TARGET_EXCEEDED`
- `COST_UNKNOWN`
- `BUDGET_EXCEEDED`

Unknown cost under a hard budget is never normalized to zero.

## 6. Ranking

Only eligible candidates are ranked.

Order:

1. HEALTHY before DEGRADED;
2. lower estimated total request cost;
3. lower p95 latency;
4. lexical model ID tie-break.

Unknown cost can remain eligible only when there is no hard budget; it ranks behind known finite cost.

The ranking is deterministic.

## 7. Fallback policy

When `allow_fallback=false`, the fallback list is empty.

When fallback is allowed, remaining eligible candidates are returned in the same deterministic ranking order.

Fallbacks never bypass hard filters.

## 8. LOCAL_SENSITIVE privacy lock

`LOCAL_SENSITIVE` forcibly normalizes to:

```text
privacy = LOCAL_ONLY
allow_cloud = false
```

A caller cannot weaken those fields by passing STANDARD privacy or cloud permission.

For LOCAL_ONLY work:

- selected locality must be LOCAL;
- every fallback locality must be LOCAL;
- cloud candidates remain visible only as rejected evidence;
- no eligible local candidate produces `MODEL_ROUTE_UNAVAILABLE`.

This is the CHAT 05 exit-gate invariant.

## 9. Route evidence

Successful decisions include:

- normalized request;
- selected model/runtime;
- fallback list;
- rejected candidates + reason codes;
- health state used;
- estimated request cost;
- deterministic route reference.

Reference format:

```text
model-route:sha256:<64 hex>
```

Same normalized facts and candidate inventory produce the same route reference regardless of candidate input order.

## 10. Runtime binding

`bindModelRouteToRuntime(...)` binds a route decision to a CHAT 04 runtime resolution.

It requires:

```text
selected.provider_id == adapter.runtime.provider
selected.runtime_id  == adapter.runtime.runtime_ref
```

Before adapter identity checks, the binding recomputes the content-addressed route digest and rejects a decision whose payload no longer matches its `model_route_ref`.

A provider/runtime mismatch also fails before Mission orchestration.

The binding passes the exact `model_route_ref` into CHAT 04, where it is preserved in the Execution Attempt.

This prevents route evidence from naming one provider/runtime while execution silently uses another.

## 11. Failure semantics

No eligible candidate throws a structured `ModelRouteUnavailableError`:

```text
code = MODEL_ROUTE_UNAVAILABLE
```

The error preserves:

- normalized request;
- per-candidate rejection evidence.

It does not silently choose a forbidden candidate.

## 12. Non-goals

CHAT 05 does not:

- execute model inference;
- fetch live provider catalogs;
- store credentials;
- authorize capabilities/connectors;
- install local models;
- hardcode a global vendor preference;
- implement retries;
- implement Cost Governor accounting;
- claim real provider quality/availability from synthetic tests.
