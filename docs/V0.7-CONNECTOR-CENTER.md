## Goal

CHAT 18 establishes the canonical external-integration lifecycle without weakening the existing CHAT 06 Capability Router.

The important separation is:

```text
connector known
!= connector connected
!= employee/resource grant
!= capability authorization
!= execution
!= verified result
```

A `CONNECTED` connector never means universal access.

## Canonical registry

Source:

`config/connector-registry.json`

Repository connector definitions must default to:

`NOT_CONNECTED`

Definitions declare:

- connector ID;
- provider;
- capabilities exposed;
- READ/WRITE modes supported;
- exact resource types;
- authentication mode;
- allowed secret-reference schemes;
- verification method.

The repository does not commit live connections or credentials.

## Lifecycle

Connector connection snapshots use:

```text
NOT_CONNECTED
CONNECTED
DISCONNECTED
REVOKED
EXPIRED
ERROR
```

Supported transitions include:

- connect;
- disconnect;
- reconnect from safe non-terminal states;
- revoke;
- expire;
- error.

`REVOKED` is terminal.

A connection expiry is enforced during authorization even if an explicit EXPIRE lifecycle event has not yet been persisted.

Connection snapshots are content-addressed:

`connector-connection:sha256:<digest>`

Each transition records the prior connection reference and increments the lifecycle sequence.

## Secret-reference-only handling

Connector Center never requires a raw API key/token/password in repository config or route evidence.

Supported credential references are bounded schemes such as:

- `connector-secret://...`
- `secret://...`
- `env://...`

Known raw secret fields such as `api_key`, `access_token`, `refresh_token`, `client_secret`, `password`, and raw `credential` fields fail validation.

The connection integrity record binds a SHA-256 hash of the credential reference.

Authorized connector routes intentionally omit the credential reference itself.

A provider bridge may receive the reference and resolve it outside Connector Center. The resolver/secret store remains outside repository state.

## Least-privilege connector grants

Safe default:

`config/connector-grants.json`

contains no grants.

A Connector Grant binds:

- employee;
- connector;
- capability;
- READ/WRITE mode;
- action;
- exact resource type + resource ID;
- issue time;
- optional expiry;
- grant evidence reference;
- optional explicit revocation evidence.

Wildcards are rejected.

Grant records are content-addressed:

`connector-grant:sha256:<digest>`

A connector grant cannot expand beyond the connector definition.

## Authorization

`authorizeConnectorAction(...)` requires all of these facts to match:

1. known connector;
2. supported capability;
3. supported READ/WRITE mode;
4. supported resource type;
5. currently CONNECTED connection;
6. exact employee grant;
7. exact capability grant;
8. exact action grant;
9. exact resource grant;
10. grant is issued, unexpired, and unrevoked.

Only then is an immutable connector route emitted:

`connector-route:sha256:<digest>`

The route contains connection and grant evidence references but no credential reference.

## Relationship to CHAT 06 Capability Router

Connector Center does not replace `packages/capability-router`.

It can emit a provider snapshot through:

`buildCapabilitySnapshotFromConnector(...)`

That snapshot proves only the connected provider/capability evidence.

The existing Capability Router still requires its own employee capability scope and exact resource grant.

Therefore:

```text
allowed connector route
+
missing capability-router resource grant
=
BLOCKED
```

This intentional double boundary prevents `CONNECTED` from becoming an authorization shortcut.

## Practical provider connector

CHAT 18 includes:

`packages/connector-center/google-ads-readonly.mjs`

It uses the already-existing Google Ads provider-neutral capabilities:

- `ads.google.read`;
- `ads.google.insights`;
- `ads.google.keywords`;
- `ads.google.creative`;
- `ads.google.verify`.

Supported operations are read-only:

- list campaigns;
- campaign insights;
- search terms;
- inspect creative;
- verify state.

The adapter exposes no write operation.

It receives a credential **reference** for the external bridge, not a raw credential.

If the provider transport reports `mutated: true`, the connector fails closed.

CHAT 18 tests this with a deterministic provider transport fixture. It does not claim a live Google Ads account was connected or queried.
