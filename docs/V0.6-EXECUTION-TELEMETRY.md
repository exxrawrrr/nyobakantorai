## Purpose

CHAT 09 replaces vague execution presentation with an inspectable projection of canonical execution records.

It does not introduce a second execution state machine and it does not create synthetic progress events.

The telemetry projection reuses:

- TaskNode v1;
- Execution Attempt v1;
- Handoff Result v1;
- Live Sandbox admission v1;
- Live Sandbox record v1.

## Canonical terminal-state rule

Visible execution state comes from the Execution Attempt record.

The projection exposes:

- `attempt_id`;
- attempt ordinal;
- exact Attempt state;
- whether that Attempt state is terminal;
- `state_source: EXECUTION_ATTEMPT_V1`.

Terminal states are:

- `BLOCKED`;
- `PARTIAL`;
- `FAILED`;
- `SUCCEEDED`;
- `CANCELLED`.

A TaskNode, handoff result, or sandbox sidecar cannot silently replace the Attempt state.

Identity mismatches fail closed.

## Telemetry contract

`packages/mission-engine/telemetry.mjs` provides:

- `buildExecutionTelemetry(...)`;
- `buildMissionTelemetry(...)`.

Each execution projection may include:

- employee identity;
- runtime provider/ref/version;
- model identity and model-route reference;
- tool IDs and capability-route references;
- start/finish timestamps;
- measured duration;
- tool-call count;
- input/output/total token counters;
- monetary cost when known;
- artifacts;
- evidence references;
- signed receipt reference;
- explicit unknowns;
- blockers;
- residual risks;
- previous Attempt / recovery checkpoint references;
- sandbox admission and record references.

## Unknown means unknown

CHAT 09 never converts unavailable counters into zero.

When canonical provider/runtime evidence is missing:

- model identity is `UNKNOWN`;
- tool IDs are `UNKNOWN`;
- usage source is `UNKNOWN`;
- duration/token/tool-call counters remain `null`;
- monetary cost remains `{ status: "UNKNOWN", amount_usd: null }`.

A RUNNING Attempt without a finish timestamp does not receive an invented elapsed duration.

## Sidecar binding

Sandbox and handoff records are optional telemetry sidecars, not replacement control state.

Before they are attached, the projection checks relevant identity fields:

- Mission ID;
- TaskNode ID;
- employee ID;
- runtime provider;
- runtime ref;
- model-route ref where present;
- sandbox admission ref;
- handoff terminal state.

Sandbox admission and record integrity validators run before their data is projected.

Tampered or mismatched sidecars are rejected.

For a task with multiple Attempts, `buildMissionTelemetry(...)` does not automatically attach a task-level sidecar to an arbitrary Attempt. Ambiguous sidecar attribution remains unknown instead of being guessed.

## Orchestrator projection

The Mission Orchestrator now returns a `telemetry` array beside the existing canonical:

- Mission;
- TaskNodes;
- Attempts;
- handoffs;
- handoff returns;
- events.

The orchestrator still creates the same canonical Attempt/TaskNode states.

Telemetry is a read projection after orchestration settlement, not a new source of execution truth.

## Public live boundary

A public response can now become `LIVE_RUNTIME` only when the live runner supplies all required canonical traceability:

- successful runtime outcome;
- TaskNode;
- Execution Attempt;
- Sandbox admission;
- Sandbox record.

The existing sandbox success checks still apply.

The telemetry projection must also validate and report a terminal `SUCCEEDED` Attempt.

Missing or inconsistent Attempt traceability produces `LIVE_VERIFICATION_FAILED`; it is not presented as live success.

The default localhost office still does not inject an arbitrary-mission live runner, so the normal `TRY LIVE AI` path remains honestly `LIVE UNAVAILABLE`.

## Evidence UI

The public `Try AI` result now includes an **EXECUTION EVIDENCE** section.

For verified live-shaped telemetry it can show:

- employee;
- Attempt and state;
- model;
- runtime;
- tools / capability routes;
- start/end/duration;
- token/tool-call/cost counters;
- artifacts;
- evidence refs;
- receipt;
- unknowns;
- blockers;
- residual risks;
- terminal-state and sandbox traceability refs.

Telemetry text is rendered through DOM text nodes / `textContent`, not injected as HTML.

Before verified live telemetry is exposed to the browser, public projection redacts secret-like, credential-URL, and private-machine-path shaped runtime/evidence/artifact/recovery references. Canonical internal telemetry remains unchanged.

Synthetic demo responses cannot surface telemetry even if an injected payload includes a telemetry-shaped object.

For deterministic demo:

`NO EXECUTION TELEMETRY · Synthetic planning only; no runtime execution is claimed.`

For unavailable/unverified live:

`NO EXECUTION TELEMETRY · Live execution was unavailable or not verified.`

## Security / scope

CHAT 09 does not:

- add provider credentials;
- expose secrets, private machine references, or private prompt content;
- create public logging of raw runtime output;
- enable external writes;
- enable paid/destructive actions;
- invent progress events;
- convert unknown cost/token data to zero;
- create verifier evidence;
- replace TaskNode / Attempt / Sandbox canonical contracts.
