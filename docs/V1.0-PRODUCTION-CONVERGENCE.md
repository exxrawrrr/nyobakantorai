## Release behavior

While any blocker remains:

- package metadata stays at **0.5.1**;
- package bump to 1.0.0 is unauthorized;
- `v1.0.0` tag creation is unauthorized;
- GitHub Release publication is unauthorized;
- tagged-asset verification is `NOT_RUN_BLOCKED`;
- post-release install smoke is `NOT_RUN_BLOCKED`;
- the manual GO gate is not reached.

## What would change the decision

A future GO requires all of the following at the same time:

- canonical real-world dataset reaches its reviewed publication gate;
- provider lifecycle maturity becomes validated with attributable provider evidence;
- representative live missions provide bounded failure/recovery evidence;
- all four production install/migration matrices remain passing and attributable to the exact release-candidate source;
- v0.9 prerequisite chain is READY;
- security and release-claim audits remain PASS;
- the owner completes the final manual GO gate on the exact release candidate.

Only then may package metadata be changed to 1.0.0 and the tag/release sequence begin.
