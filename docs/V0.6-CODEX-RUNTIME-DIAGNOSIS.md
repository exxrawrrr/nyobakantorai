## Root cause

The current Codex live-reference failure is caused by provider quota exhaustion, not by the Codex execution adapter.

A minimal direct probe using the adapter's exact live flags returned a Codex JSON error stating that the ChatGPT/Codex usage limit had been reached. The CLI reported a retry time of Oct 5, 2026 9:44 AM; the CLI output did not state a timezone.

The process then exited with status 1, which correctly remained a failed and unverified runtime attempt.

- `codex doctor --json`: auth OK, provider HTTP reachability OK, WebSocket handshake OK, sandbox provisioning complete.
- Codex CLI version: `0.154.0`.
- Exact adapter flags are accepted by `codex exec --help`.
- Historical canonical Codex live evidence on the same CLI version completed successfully.
- The Codex adapter blob in that successful proof and current `main` is byte-identical.
- Current minimal direct probe fails with the explicit usage-limit error.

## Safe diagnostic hardening

The adapter now classifies a matching non-zero Codex failure as:

`PROVIDER_QUOTA_EXHAUSTED`

Only the static category is exposed through normalized output. Raw provider stdout/stderr, URLs, reset text, credentials, and account details remain excluded from the public record.

Unknown non-zero provider failures remain:

`PROVIDER_FAILURE_UNCLASSIFIED`

The generic RuntimeExecutionAdapter terminal category remains `RUNTIME_REPORTED_FAILURE`; CHAT 07B does not broaden the generic runtime contract.

## Residual environment warning

Codex also emitted a non-fatal skill-loading warning for:

`%USERPROFILE%\.codex\skills\growthops-engineering\SKILL.md`

Inspection showed valid YAML frontmatter preceded by a UTF-8 BOM. Codex 0.154.0 treats that BOM as preventing the frontmatter delimiter from appearing at byte zero.

This warning is not the cause of the current process exit: the turn continued until the explicit quota failure. The global skill file was not modified. The under-development `skip_host_skill_discovery` feature was tested and did not suppress this warning, so it is not added to the canonical adapter.
