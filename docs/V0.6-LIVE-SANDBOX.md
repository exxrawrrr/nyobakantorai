## 2. Boundary

The execution chain is:

```text
Mission / TaskNode
   -> Model Route
   -> Capability Routes
   -> Live Sandbox admission
   -> RuntimeExecutionAdapter
   -> Sandbox settlement
```

The Live Sandbox does not grant model or capability permission.

It only constrains an already-declared bounded execution.

Therefore:

```text
sandbox admitted != production authorized
quota available != approval granted
model route != capability route
capability route != execution proof
sandbox PASS != independent verification
```

## 3. Default policy

The committed default is deliberately conservative:

```text
risk class: READ_ONLY only
runtime providers: codex / hermes
max duration: 45 seconds
max task-visible tool calls: 0
max input tokens: 12,000
max output tokens: 4,000
max total tokens: 16,000
task-visible network hosts: none
fallback: disabled
temporary workspace: required
external write: forbidden
credential exposure: forbidden
hard USD cost ceiling: none
```

A null hard cost ceiling does **not** mean zero cost.

It means the current live provider substrate cannot prove actual monetary cost.

Cost remains explicitly `UNKNOWN`.

## 4. Cost semantics

Cost is one of:

```text
KNOWN(amount_usd)
UNKNOWN
```

Invalid combinations fail validation.

Examples:

```text
UNKNOWN + amount_usd=0
-> invalid

KNOWN + amount_usd=null
-> invalid
```

Unknown cost is never converted to zero.

When a hard cost ceiling is configured:

- projected cost must be KNOWN before admission;
- known projected cost above ceiling is blocked;
- unknown actual cost makes quota verification PARTIAL;
- known actual cost above ceiling makes settlement FAIL.

Full ledger/accounting remains a later Cost Governor milestone.

## 5. Admission

Admission binds:

- Mission ID;
- exact TaskNode ID;
- risk class;
- runtime provider;
- declared model identity state;
- optional model-route ref;
- capability-route refs;
- task-visible tools;
- task-visible network hosts;
- fallback disclosure;
- credential-exposure declaration;
- projected duration/tool/token/cost usage.

Admission output is content-addressed:

```text
sandbox-admission:sha256:<64 hex>
```

The digest is recomputed during validation.

## 6. Exact task binding

The runtime integration checks before adapter prepare:

```text
admission.task_id == runtime task.task_id
admission.risk_class == runtime task.risk_class
admission.provider_id == adapter.runtime.provider
```

Mismatch fails before runtime prepare/execute.

This prevents a valid admission for one task/risk/provider from being reused for another.

## 7. Quota ceilings

Admission fails closed when projected:

- duration;
- tool calls;
- input tokens;
- output tokens;
- total tokens;
- known cost

exceed the configured ceilings.

Actual known usage is checked again during settlement.

## 8. Unknown actual usage

Some provider/runtime paths do not expose reliable token/tool/cost counters.

Missing values stay:

```text
null / UNKNOWN
```

They are not normalized to zero.

When a required actual dimension is unavailable:

```text
quota_status = PARTIAL
record status = PARTIAL
```

unless another failure already makes the record FAIL.

This keeps the evidence truthful.

## 9. Tool/network allowlists

Task-visible tool IDs and task-visible network hosts must be explicit subsets of policy allowlists.

Default policy allows neither.

The provider transport needed for the runtime/model itself is treated separately from arbitrary task egress.

CHAT 07 does not broaden the task's network permissions.

## 10. Fallback

Fallbacks must be declared before execution.

Default:

```text
allow_fallback = false
```

The sandbox does not invent or silently switch providers/models.

The real-provider exit attempt used no fallback.

## 11. Credential boundary

The dispatch declaration must say:

```text
credentials_exposed_to_task = false
```

The sandbox does not print, copy, mint, or persist provider credentials.

Provider authentication remains runtime/user owned.

## 12. Settlement

A settlement record checks:

- runtime success;
- runtime provider identity;
- actual known quota usage;
- temporary-workspace evidence;
- production-repository mutation;
- prohibited actions;
- external-write evidence;
- cleanup attempted/ok.

Record reference:

```text
sandbox-record:sha256:<64 hex>
```

## 13. Teardown truth

A successful teardown requires:

```text
cleanup.attempted = true
cleanup.ok = true
temporary_workspace_only = true
production_repo_changed = false
```

A model/runtime failure may still have:

```text
teardown_verified = true
```

That means disposable-state cleanup succeeded.

It does not convert the failed model task into a success.

## 14. Canonical live-run integration

The existing portability live runner now accepts optional sandbox input.

Without sandbox input, its original behavior remains intact.

The CLI:
