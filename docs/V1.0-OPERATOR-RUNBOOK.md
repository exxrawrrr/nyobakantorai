# v1.0 Production Release Operator Runbook

Status: **ACTIVE FAIL-CLOSED RUNBOOK**  
Candidate: `v1.0.0`

## Rule zero

Never create, move, or publish the `v1.0.0` tag while `npm run v1.0:readiness:require-ready` exits non-zero.

## Pre-release sequence

1. Start from clean exact `main` and record its 40-character commit SHA.
2. Run `npm run verify`.
3. Run all production install matrices:
   - `npm run release:matrix:one-worker`
   - `npm run release:matrix:subset`
   - `npm run release:matrix:full`
   - `npm run release:matrix:lifecycle`
4. Run `npm run v1.0:readiness:check` and inspect every blocker.
5. Confirm the canonical real-task dataset reached its reviewed publication gate with zero false-success.
6. Confirm provider lifecycle maturity is `validated`, not merely detected/configured/partial.
7. Confirm representative live Missions include observed failures and independently attributable bounded recoveries.
8. Run the repository security/public audits through the normal verification path.
9. Confirm the v0.9 prerequisite chain is READY.
10. Only after every technical gate is clear, record a bounded owner manual GO decision.

## Promotion sequence

Only after the readiness evaluator returns READY:

1. Change package/release metadata to `1.0.0` in a reviewed release-candidate PR.
2. Require Linux, Windows, and minimum-version CI on the exact PR head.
3. Merge with an exact-head guard.
4. Require the same three-lane verification on exact promoted `main`.
5. Re-run `npm run v1.0:readiness:require-ready` on that exact commit.
6. Create annotated tag `v1.0.0` on that exact commit.
7. Let the release workflow build immutable core ZIP/TAR assets, employee packs, manifests, and SHA-256 files.
8. Verify the tagged workflow and release assets before calling the release published.

## Post-release seal

After publication:

1. Download the published immutable asset, not mutable `main`.
2. Verify its release manifest and SHA-256 checksum.
3. Install into a new disposable/clean location.
4. Run preflight, build, and smoke checks from the installed release.
5. Record the asset digest, tag commit, workflow run, and smoke evidence.
6. If any check fails, do not rewrite evidence; publish a corrective release only through the same gate.

## Current CHAT 30 behavior

When technical evidence is incomplete, the correct result is **NO_GO**. Keep the highest truthful stable pre-v1 package/version unchanged and leave tagged-asset/post-release smoke as `NOT_RUN_BLOCKED`.
