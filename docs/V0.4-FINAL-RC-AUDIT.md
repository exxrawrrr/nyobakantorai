## GitHub release workflow least privilege

A reviewer finding was fixed during this audit.

Previously the complete `release-gate` job had:

```yaml
permissions:
  contents: write
```

even though write access is only required when publishing a tagged GitHub Release.

The workflow is now split so that:

- normal verification/build/artifact generation runs with `contents: read`;
- a separate `publish-tagged-release` job runs only for `refs/tags/*`;
- only that tag-only publish job receives `contents: write`;
- publish downloads the already-verified manifest and employee-pack artifacts from the release-gate job.

This reduces the token permissions available to dependency installation, tests, build, and packaging.
