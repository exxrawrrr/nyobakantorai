## What CHAT 28 adds

## Safety boundaries

Mission Control cannot create an alternative execution path. Queue selection receives only already-runnable TaskNode IDs and the Mission Engine validates that any selected batch is a unique subset within `maxConcurrency`.

A pause is evaluated only at the orchestrator loop boundary, after the previous batch has settled. A paused result therefore contains no RUNNING TaskNode or RUNNING Execution Attempt. Pending work stays inspectable and resumable from a content-addressed checkpoint.

Adaptive planning in CHAT 28 is proposal-only. The proposal cannot request capabilities outside its declared authority baseline and always reports `owner_review_required=true`, `automatic_apply_allowed=false`, and `authority_widening_allowed=false`.

Checkpoint-aware provider rerouting delegates provider choice to `chooseRecoveryProvider()` from the existing recovery package. Mission Control does not invent a provider or bypass that allowlist.

## Sandbox hardening claim boundary

The hardened profile is an **application-level guard**, not OS/container isolation. It requires declared proof of:

- temporary-workspace-only filesystem access;
- read-only production repository and no host-home access;
- ephemeral browser profile, no user-profile reuse, no browser credential-store access;
- allowlist-only network hosts and DNS-rebinding protection;
- bounded process/workspace resource estimates;
- reference-only credentials with no credential values in task payload and no secret environment injection into the task.

The hardening decision is content-addressed and fail-closed.
