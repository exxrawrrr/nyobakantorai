## Pricing / SKU metadata

CHAT 23 does not hard-code numeric Google prices.

Reason:

- provider prices can change;
- region/billing context can vary;
- a stale numeric price creates false cost confidence.

Instead, the policy pins:

- reviewed FieldMask profile;
- highest expected SKU tier;
- official pricing/billing source;
- source review date;
- billing rule that the request is charged according to the highest SKU triggered by requested fields.

Numeric price remains runtime/billing evidence, not static truth.

## Search bounds

Provider and internal bounds are both enforced.

### Nearby Search

- exact circle required;
- radius > 0;
- provider maximum 50,000 m;
- result count 1–20;
- internal area diameter also must remain inside the configured mission bound.

### Text Search

CHAT 23 intentionally uses one bounded page only:

- exact text query;
- exact rectangular `locationRestriction`;
- no implicit IP-bias fallback;
- page size 1–20;
- page number fixed to the CHAT 23 single-page bound;
- internal search-area diagonal maximum 100 km.

Search expansion, pagination, and multi-query coverage belong to CHAT 24.

This avoids prematurely storing paging state or implying completeness from one query.

## Ephemeral response handling

Provider response content is marked:

`EPHEMERAL_ONLY`

The in-memory response may be used during the active request lifecycle.

It is not a durable artifact.

The durable evidence builder intentionally drops:

- display name;
- formatted address;
- location;
- types;
- Google Maps URI;
- provider attribution payload;
- any other provider response field.

The durable evidence contains only allowed Place ID records and policy/request metadata.

## Place ID retention

Place ID is the only provider-returned place field permitted by the CHAT 23 durable-storage policy.

A durable Place ID record contains:

- provider;
- Place ID;
- first-seen timestamp;
- refresh-due timestamp;
- policy ref;
- record ref.

Refresh window:

`365 days`

This reflects Google's recommendation to refresh stored Place IDs older than approximately 12 months.

The durable validator rejects accidental additions such as:

- `displayName`
- `formattedAddress`
- rating;
- website;
- phone;
- reviews;
- coordinates.

## Attribution

When Google Places provider content is displayed outside a Google Map, the policy requires Google Maps attribution.

When provider/third-party attribution objects are returned, they are preserved in the ephemeral display requirements.

CHAT 23 field profiles intentionally do not enable photos or reviews, avoiding their additional author/source attribution workflow until a later reviewed contract exists.

Attribution requirements are separate from retention permission:

```text
must display attribution
!=
may store provider content
```
