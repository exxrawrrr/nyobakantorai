## Goal

CHAT 24 turns incomplete bounded discovery into provenance-aware research profiles without pretending that one provider/query is exhaustive.

The pipeline is:

```text
bounded expansion
  -> discovery working set
  -> conservative identity resolution
  -> public-source enrichment
  -> field confidence/conflict resolution
  -> explainable versioned scoring
  -> independent Siti verification
  -> CSV/XLSX/report/evidence export
```

Every stage preserves its own evidence boundary.

## Search expansion

Implementation:

`packages/geo-intelligence/expansion.mjs`

Expansion is bounded by:

- maximum keywords;
- maximum geographies;
- maximum total queries;
- maximum queries per geography;
- reviewed Geo Core area bounds;
- CHAT 23 production FieldMask profiles.

Every generated query is bound to a real Geo Core request ref.

Current expansion defaults to:

`TEXT_SEARCH_IDENTITY`

so the first discovery pass favors identity/Place-ID retrieval rather than pulling broad provider content.

Expansion plans explicitly contain:

`completeness_claim: false`

Adaptive keywords do not auto-run.

They become a proposal with:

- reason;
- evidence refs;
- `review_required: true`;
- `approved: false`.

This preserves human review before the system changes its search strategy.

## Identity resolution / dedupe

Implementation:

`packages/geo-intelligence/identity.mjs`

Identity evidence includes:

- exact Place ID;
- canonical domain;
- normalized phone;
- normalized address;
- high name-token similarity;
- short geographic distance.

The merge policy is intentionally conservative.

Strong rules:

- exact Place ID is strongest identity evidence;
- different non-empty Place IDs are a hard conflict;
- exact domain/phone are strong signals;
- fuzzy name similarity alone can never auto-merge;
- cluster merge is refused if it would introduce conflicting Place IDs.

Each pair receives:

- numeric score;
- decision: `MERGE`, `REVIEW`, or `KEEP_SEPARATE`;
- hard-conflict state;
- strong-signal count;
- name similarity;
- distance;
- explicit rationale;
- content-addressed comparison ref.

Clusters preserve every original source record ref.

No duplicate is silently discarded.

## Provider-content boundary

Discovery records may contain ephemeral provider fields while the identity resolver is running.

Those records are working-set evidence only.

The durable business profile does **not** copy provider name/address/phone/location fields into its durable result merely because Google Places returned them.

The only Google Places value that survives directly into durable profile identity is the Place ID allowed by CHAT 23 policy.

Other durable profile fields must come from independently attributable public sources.

## Public web/source enrichment

Implementation:

`packages/geo-intelligence/enrichment.mjs`

Allowed source classes:

- official website;
- public directory;
- public organization page;
- public news;
- other public web.

Safety boundaries:

- HTTP/HTTPS only;
- public/no-auth/read-only;
- URL userinfo forbidden;
- localhost/private-network targets rejected;
- credentials forbidden;
- raw page persistence forbidden;
- maximum response size policy;
- retrieval timeout policy;
- maximum sources per profile;
- maximum sources per mission;
- access-control bypass forbidden.

A durable source record stores only:

- public URL;
- source class;
- retrieval timestamp;
- normalized structured claims;
- confidence;
- claim refs.

It does not store a raw HTML/page body.

## Field provenance and conflicts

Each field is resolved from claim groups using:

- source-type trust;
- source claim confidence;
- freshness window;
- normalized value equivalence.

A profile field is either:

- `RESOLVED`; or
- `CONFLICT`.

Close competing evidence is not silently overwritten.

A conflicted field stores every candidate value with:

- evidence weight;
- source refs.

The durable field value remains `null` until the conflict is resolved.

## Versioned scoring

Implementation:

`packages/geo-intelligence/scoring.mjs`

Current model:

`geo-business-fit-v1@1.0.0`

Maximum:

`100`

Criteria:

- identity strength — 20;
- source diversity — 15;
- official web presence — 15;
- business type fit — 20;
- public contactability — 10;
- geographic fit — 10;
- evidence freshness — 10.

Every positive point must carry evidence refs.

Missing/conflicted evidence contributes zero rather than an assumed positive value.

A score contains:

- model ID/version;
- total;
- per-criterion points;
- max points;
- rationale;
- evidence refs;
- content-addressed score ref.

The pre-verification state is:

`PENDING_VERIFICATION`

Scoring does not itself create a verified lead/profile.

## Independent Siti verification

Implementation:

`packages/geo-intelligence/verification.mjs`

CHAT 24 reuses the existing canonical:

`runSitiVerification(... kind: "RESEARCH")`

It does not invent a second QA model.

The profile author is a non-Siti employee such as Alex/Ratri/Nara.

Siti checks:

- exact profile identity ref;
- exact score ref/model version;
- provenance refs;
- scoring rationale;
- dedupe rationale;
- required research evidence;
- remaining profile conflicts.

Siti cannot author and verify the same profile.

A profile with unresolved material conflict cannot become VERIFIED.

The Siti verification record is then bound separately to:

- exact `profile_ref`;
- exact `score_ref`;
- exact canonical `verification_ref`.

Binding ref:

`geo-profile-verification:sha256:<digest>`

This prevents exports from accidentally associating the wrong QA result with a different profile.

## Verified profile finalization

`finalizeVerifiedProfile(...)` requires:

- matching profile/score;
- matching verification binding;
- Siti reviewer;
- independent review;
- review state PASS;
- decision VERIFIED.

Without those conditions, the profile cannot receive:

`VERIFIED_PROFILE`

## Research export pack

Implementation:

- `packages/geo-intelligence/exports.mjs`
- `packages/geo-intelligence/xlsx.mjs`

Outputs:

- `profiles.csv`;
- `profiles.xlsx`;
- `report.md`;
- `evidence.json`.

The XLSX writer is a small deterministic dependency-free OpenXML/ZIP writer.

No extra npm supply-chain dependency is added.

### Default export rule

Final export defaults to:

`require_all_verified: true`

Every exported profile must have an exact Siti PASS binding.

Draft/unverified research export is still possible only by explicitly setting:

`require_all_verified: false`

and every row remains visibly marked `NOT_RUN` / non-verified.

## Evidence pack

The evidence JSON contains:

- expansion plan/query refs;
- profile refs;
- cluster refs;
- public source refs/types;
- score refs/model/version/contributions;
- verification/binding refs;
- verification state.

It deliberately excludes:

- raw Google Places provider payload;
- raw public webpage body;
- credentials;
- private page content.

It also repeats:

`completeness_claim: false`

## XLSX / CSV semantics

Exports are research artifacts, not CRM writes.

CHAT 24 does not:

- write leads to a CRM;
- send outreach;
- create provider-side mutations;
- claim qualification is final merely from score;
- claim market completeness.

CRM-ready lifecycle belongs to CHAT 25.

## Claim boundary

CHAT 24 proves deterministic research-pipeline behavior and evidence contracts.

It does not claim:

- a live Places discovery mission was run;
- the public web was exhaustively crawled;
- every business in an area was found;
- public sources are always correct;
- scores are universal truth;
- unverified profiles are CRM-ready;
- outreach is authorized.

The canonical claim remains:

> Expanded searches and merged profiles describe observed bounded coverage only. They never prove exhaustive market coverage.

CHAT 25 may turn verified research into map/CRM-ready operational artifacts, but must preserve these provenance and approval boundaries.
