## Readiness computation

`packages/release-readiness/index.mjs` computes v0.6 release readiness from canonical acceptance evidence.

The readiness ledger must fail validation when:

- its declared blockers differ from the canonical blocked acceptance criteria;
- its declared decision differs from the computed decision;
- a blocked candidate authorizes the package version bump;
- a blocked candidate authorizes a stable tag or publication;
- canonical acceptance counts drift;
- a required acceptance criterion disappears;
- live observation safety/teardown truth drifts;
- durable release surfaces disappear.

A valid `BLOCKED` readiness state is allowed to pass validation. This proves the ledger is internally consistent; it does **not** authorize release.

## Release workflow guard

Tagged publication now has two fail-closed checks:

1. the Git tag must exactly match `v<package.json version>`;
2. tag `v0.6.0` must pass `npm run v0.6:readiness:require-ready`.

At the current blocked state:

- `npm run v0.6:readiness:check` should exit 0 and report `BLOCKED`;
- `npm run v0.6:readiness:require-ready` should exit nonzero;
- creating or publishing `v0.6.0` is not authorized.
